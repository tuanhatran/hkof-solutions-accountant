# Frontend conventions

## Stack and layout

- React 19, TypeScript strict, Vite, TanStack Query, Zustand, React Hook Form + Zod, Tailwind.
- `frontend/src/`: `api/`, `pages/`, `components/`, `lib/`, `state/`, `hooks/`.
- API types are generated by `npm run gen:api` into `frontend/src/api/schema.ts`.

## Code rules

- No `any`. No authoritative monetary calculation on the client. An immediate estimate may
  be displayed, but the backend remains the reference.
- Every HTTP call goes through `frontend/src/api/endpoints.ts`.
- Query hooks and keys live in `frontend/src/api/queries.ts`. Invalidate with `queryKeys`
  constants, never string literals. Use a prefix key (for example
  `queryKeys.expenseItemsAll`) when several list variants exist.
- Forms: React Hook Form + Zod schemas in `frontend/src/lib/validation.ts`.
- User feedback: `toast` from `frontend/src/state/toasts.ts`.
- API amounts are strings. Use the existing parsers and formatters (`parseAmount`,
  `parsePercentage`, `formatEUR`, `formatDate`, `formatMonth`, `formatPeriod`).
- User-facing text and error messages are in French. Loading, error and empty states are
  mandatory.
- Accessibility: labels, keyboard navigation, `aria-live` for asynchronous updates.
- E2E selectors: `data-cy` attributes from the specification, never style selectors.
- Never display the LLM key or send it back empty by accident.

## Code language

- Component names, variables, functions, comments and tests in English.
- Rendered strings, labels, alt text and toasts in French.
- Exported helper names stay consistent with the codebase (`parseAmount`, `formatEUR`).

## CSS conventions

- Every styled component has a colocated `<Component>.css` next to its `.tsx`,
  imported by the component (`import "./Component.css";` first), never by `main.tsx`
  and never through a barrel.
- Class names are prefixed with the component file name in kebab-case:
  `PageHeader.css` → `.page-header`, `.page-header-title`,
  `.page-header-title-active`.
- Each component CSS starts with `@reference "<relative path>/index.css";` (the path is
  relative to the CSS file's own depth), then puts every rule inside
  `@layer components`. `main.tsx` imports `./index.css` first so the cascade holds.
- Design-system primitives (`card`, `btn`, `field`, `badge`, …) stay on the element and
  are never copied: `@apply card` / `@apply btn` do not resolve in Tailwind v4. Add only
  the component-specific class: `className="card expense-result-card"`.
- Values come from tokens only (`var(--color-*)`, `var(--shadow-*)`, `var(--font-*)`) or
  from `@apply <utility>`; no hex literal in component CSS. A hex already equal to a
  token reuses that token.
- Conditional variants are a separate class combined with `cn()`; no long conditional
  utility strings.
- A component CSS stays under 300 lines; split it by block when it grows.

## PDF preview

- Preview through `react-pdf`, never an iframe.
- Debounce 400 ms, `AbortController`, previous preview kept under a veil.
- The preview persists nothing; the generate button produces the final document.

## Tests

- Vitest, files `src/**/*.test.ts(x)`, setup `src/test/setup.ts`.
- Cypress in `frontend/cypress/`.

## Verification

```bash
cd frontend && npm run typecheck && npm test && npm run build
```
