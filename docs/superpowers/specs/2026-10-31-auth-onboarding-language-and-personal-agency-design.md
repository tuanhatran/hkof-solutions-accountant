# Auth & Onboarding Language Toggle, Personal Agency, Dedicated Backend Agency & Onboarding Resume Flow Specification

Date: 2026-10-31 · Status: Draft for User Approval · Scope: Full stack (DB migration, backend domain & services, OpenAPI contract, frontend auth/onboarding/dashboard/settings, i18n FR/EN toggle, tests).

---

## 1. Intent and Why

1. **Language Accessibility**:
   The standalone public auth pages (`/login`, `/register`, `/confirm-email`, `/password`) and the onboarding flow (`/welcome`) lack language selection controls. Users need immediate FR/EN switching before and during onboarding.

2. **Domain Separation (Agency vs. Company)**:
   Real Estate Agency management belongs to the rental/LMNP module (`lmnpEnabled`), not the corporate employer expense module (`MODULE_COMPANY` / `companyEnabled`). Calling `/api/companies` during real estate onboarding and dashboard loading caused `403 MODULE_COMPANY_DISABLED` errors for accounts without the company module.

3. **Personal Agency vs. Professional Agency**:
   Landlords managing properties in their own name ("en nom propre") do not have commercial entities (no SIREN/SIRET, no legal form, no registered headquarters address). They need a "Personal Agency" ("Agence personnelle") option that streamlines onboarding and dashboard displays.

4. **Agency Profile Management in Settings (`/settings/agency`)**:
   Users must be able to view and update their agency profile after onboarding—specifically enabling transition between Personal Agency and Professional Agency as their business evolves.

5. **Flexible Onboarding Progression & Resume Flow**:
   Onboarding should not be an inescapable trap. Progress (steps and draft input) must be saved so users can leave or skip to the dashboard, see their onboarding progress directly on the dashboard, and resume seamlessly where they left off.

## 2. Goals

### 2.1 Language Toggle
- Integrate `LanguageSelector` into `AuthFrame` (`AuthPage.tsx`) covering `/login`, `/register`, `/confirm-email`, and `/password`.
- Integrate `LanguageSelector` into the `OnboardingPage` header (`/welcome`).
- Maintain language persistence via `localStorage` under `homeofficeexpenses.lang` and keep `document.documentElement.lang` synced.

### 2.2 Onboarding Step 1 — Personal Agency
- Add a checkbox "Personal Agency" ("Agence personnelle", `data-cy="input-onboarding-personal-agency"`).
- Dynamic visibility:
  - When checked: `legalForm`, `sirenSiret`, and `agencyAddress` are hidden; only `agencyName` remains.
  - When unchecked: all 4 fields are visible and validated.
- Validation: When `isPersonalAgency` is true, corporate fields are optional/omitted.

### 2.3 Backend Dedicated Agency Entity & API
- **Flyway Migration `V30__agency.sql`**:
  ```sql
  CREATE TABLE agency (
      id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
      user_id BIGINT NOT NULL REFERENCES app_user (id),
      name VARCHAR(255) NOT NULL,
      is_personal BOOLEAN NOT NULL DEFAULT FALSE,
      manager_name VARCHAR(255),
      legal_form VARCHAR(100),
      siren VARCHAR(9),
      siret VARCHAR(14),
      address VARCHAR(255),
      created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
      updated_at TIMESTAMP WITH TIME ZONE
  );
  CREATE UNIQUE INDEX ux_agency_user_id ON agency (user_id);

  -- Backfill existing users who already completed onboarding
  INSERT INTO agency (user_id, name, is_personal, manager_name, legal_form, siren, siret, address, created_at)
  SELECT u.id,
         COALESCE(c.name, 'Agence ' || COALESCE(p.name, u.email)),
         FALSE,
         COALESCE(c.manager_name, p.name),
         c.legal_form,
         c.siren,
         c.siret,
         c.address,
         CURRENT_TIMESTAMP
  FROM app_user u
  LEFT JOIN (
      SELECT DISTINCT ON (user_id) user_id, name, manager_name, legal_form, siren, siret, address
      FROM company
      WHERE deleted = FALSE
      ORDER BY user_id, id ASC
  ) c ON c.user_id = u.id
  LEFT JOIN (
      SELECT DISTINCT ON (user_id) user_id, name
      FROM person
      WHERE deleted = FALSE
      ORDER BY user_id, id ASC
  ) p ON p.user_id = u.id
  WHERE u.onboarding_completed = TRUE
  ON CONFLICT (user_id) DO NOTHING;
  ```
- **Backend Architecture**:
  - Entity: `Agency.java` (`domain/`).
  - Repository: `AgencyRepository.java` (`findByUserId(Long userId)`).
  - Service: `AgencyService.java` (`getForCurrentUser()`, `saveForCurrentUser(AgencyRequest)`).
  - Controller: `AgencyController.java` (`GET /api/agency`, `PUT /api/agency`).
  - Contract: `openapi/openapi.yaml` defines `AgencyDto` and `AgencyRequest`.
  - Security/Access: Gated under `LMNP_PREFIXES` in `ModuleAccessFilter.java` (dependent on `lmnpEnabled`, independent of `companyEnabled`).
  - Data seeding: Update `DataInitializer.java` to seed an agency for dev/test accounts.

### 2.4 Decoupling from `/api/companies`
- Remove all calls to `api.companies.*` and `ensureAgency` from `OnboardingPage.tsx`.
- Save agency info via `api.agency.save(...)`.
- In `DashboardPage.tsx`, replace `useCompanies()` with `useAgency()`.

### 2.5 Onboarding State Persistence, Skip & Resume Flow
- **Persistence**:
  - Persist the onboarding draft and step in user-scoped `localStorage` (`homeofficeexpenses.onboarding.<userId>`).
  - Reload saved state upon mounting `/welcome`.
- **Skip / Ignore**:
  - In `OnboardingPage.tsx`, provide a secondary action button: *"Passer au tableau de bord"* ("Skip to dashboard", `data-cy="btn-skip-onboarding"`).
  - Update `RequireAuth` in `router.tsx` to allow navigating to `/dashboard` even if `onboardingCompleted === false` once the user opts to bypass the initial landing or navigates via the app.
- **Dashboard Progress Widget**:
  - When `user.onboardingCompleted === false`, `DashboardPage.tsx` renders a prominent progress banner/card:
    - Lists the 4 onboarding steps with completion badges (Profile, Properties, Leases, Summary).
    - CTA button *"Reprendre l'inscription"* ("Resume onboarding", `data-cy="btn-resume-onboarding"`) redirecting to `/welcome` with the saved draft step intact.

### 2.6 Post-Onboarding Agency Profile Management (`/settings/agency`)
- In `LmnpPage.tsx` (`/settings/agency`), add an **"Agence"** tab alongside *"Baux"* and *"Personnes"*.
- Component `AgencySection.tsx`:
  - Loads agency data via `useAgency()`.
  - Form allowing switching between Personal Agency and Professional Agency (`isPersonalAgency` toggle).
  - Editable fields: Agency name, Manager name, Legal form, SIREN/SIRET, Headquarters address (with conditional display when personal agency is active).
  - Save action calling `PUT /api/agency` with success toast in French and cache invalidation.

## 3. Non-Goals

- Modifying the Company module (`/api/companies`, `CompanyDto`, `ExpenseStatement`, etc.), which remains reserved for corporate home-office expenses.
- Changing `CalculationService` or the core monetary calculations.
- Modifying rent receipt PDF templates or document layout.

---

## 4. Anti-Goals

- Ever calling `/api/companies` or `useCompanies()` from real-estate-specific pages (`OnboardingPage`, `DashboardPage`, `LmnpPage`).
- Overwriting corporate `company` records when creating or editing an agency.
- Exceeding the 300-line limit for any production class or component (e.g. keeping `AgencySection.tsx`, `OnboardingProgressCard.tsx` modular).
- Forcibly locking users into `/welcome` without any possibility to access the dashboard.

---

## 5. Constraints

- **Language Policy**: Code, tests, and documentation in English; user-facing labels and validation messages in French with English i18n translations.
- **Test Coverage**: Changed-line test coverage >= 80% on backend and frontend (`scripts/diff-coverage.sh`).
- **OpenAPI**: OpenAPI updated first, frontend types generated via `npm run gen:api`.

---

## 6. Approaches Considered

1. **Approach 1 (Client-Side Storage Only)**: Rejected per user selection (needs multi-device and server persistence).
2. **Approach 2 (Dedicated Backend Agency Entity + Settings & Onboarding Resume Flow - Selected)**:
   - Full domain independence.
   - Server-persisted agency profile.
   - Flexible onboarding resume flow with dashboard progress card.
   - Comprehensive settings management.

## 7. Component & Contract Details

### 7.1 OpenAPI Specification (`openapi/openapi.yaml`)
```yaml
/api/agency:
  get:
    summary: Get current user's agency profile
    operationId: getAgency
    responses:
      '200':
        content:
          application/json:
            schema:
              $ref: '#/components/schemas/AgencyDto'
      '204':
        description: No agency profile set yet
  put:
    summary: Create or update current user's agency profile
    operationId: saveAgency
    requestBody:
      required: true
      content:
        application/json:
          schema:
            $ref: '#/components/schemas/AgencyRequest'
    responses:
      '200':
        content:
          application/json:
            schema:
              $ref: '#/components/schemas/AgencyDto'

components:
  schemas:
    AgencyDto:
      type: object
      required:
        - id
        - name
        - isPersonal
      properties:
        id:
          type: integer
          format: int64
        name:
          type: string
        isPersonal:
          type: boolean
        managerName:
          type: string
          nullable: true
        legalForm:
          type: string
          nullable: true
        siren:
          type: string
          nullable: true
        siret:
          type: string
          nullable: true
        address:
          type: string
          nullable: true
    AgencyRequest:
      type: object
      required:
        - name
        - isPersonal
      properties:
        name:
          type: string
        isPersonal:
          type: boolean
        managerName:
          type: string
          nullable: true
        legalForm:
          type: string
          nullable: true
        siren:
          type: string
          nullable: true
        siret:
          type: string
          nullable: true
        address:
          type: string
          nullable: true
```

### 7.2 UI Structure
1. **`AuthFrame`**: Top-right `LanguageSelector`.
2. **`OnboardingPage`**: Header `LanguageSelector`, "Passer au tableau de bord" link, local state persistence.
3. **`OnboardingStepProfile`**: "Agence personnelle" checkbox toggles corporate fields.
4. **`DashboardPage`**: Displays `OnboardingProgressCard` if `!onboardingCompleted`, displays agency info via `useAgency()`.
5. **`AgencySection` (`/settings/agency`)**: Edit agency identity, toggle Personal vs. Professional, save via `PUT /api/agency`.
